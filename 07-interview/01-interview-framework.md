# 01 · 面试框架：45 分钟的时间预算与评分信号

> 系统设计面试考的不是"你会不会设计系统"，是"**在信息不全、时间不够的情况下，你能不能带着别人走完一条可辩护的决策路径**"。
> 大多数人挂在时间管理和收敛，不是挂在知识。

---

## 1. 时间分配表：把 45 分钟当容量规划来做

面试是一个**有硬 deadline 的实时系统**。你只有一次机会分配预算，超支就要降级。

| # | 阶段 | 45 min 档 | 60 min 档 | 必须交付的东西（面试官会检查） |
|---|---|---|---|---|
| 0 | 寒暄 / 题面 | 2 | 2 | — |
| 1 | **需求澄清**（requirements clarification） | 5–8 | 8 | 白板左上角一张 SLO 卡片：QPS / 数据量 / p99 / 可用性 / 范围外 |
| 2 | **容量估算**（capacity estimation） | 5 | 5 | 三个数：峰值 QPS、稳态数据量、月成本量级 |
| 3 | **高层设计**（high-level design） | 10–12 | 14 | 一张能跑通主链路的图 + 核心 API 签名 + 数据模型骨架 |
| 4 | **深挖**（deep dive） | 15–20 | 25 | 2–3 个组件的内部机制、参数取值、失败模式 |
| 5 | **取舍与演进**（tradeoffs and evolution） | 5 | 5 | v0 / v1 / 撞墙条件 / 撞墙信号 |
| 6 | **反问** | 3 | 3 | 2 个有信息量的问题 |

**三条止损规则（比时间表本身更重要）：**

1. **澄清超过 8 分钟就停。** 说："我先按 A 假设往下走，如果时间允许再回来讨论 B。" 澄清阶段超时是最常见的死法 —— 面试官看到的是"这个人问不完问题也不敢开始"。
2. **高层设计画完就立刻**说"我准备深挖 X 和 Y，你想先看哪个？" —— 把深挖的选择权交出去，避免你深挖了半天面试官不感兴趣的部分。
3. **还剩 8 分钟时无条件切到阶段 5**，哪怕深挖没讲完。**没有收敛的设计题，评分上等同于没做完。**

```
时间轴（45 min）
0    2         10          15              27                    42   45
├────┼─────────┼───────────┼───────────────┼─────────────────────┼────┤
 题面  需求澄清   估算        高层设计         深挖 2–3 个点          收敛 反问
      ↑写SLO卡   ↑写3个数    ↑画图+API        ↑面试官主导            ↑你主导
                                             ← 这里是唯一的加分区 →
```

**关键判断**：阶段 1–3 是**保底分**（做对了不加分，做错了直接出局），阶段 4–5 才是**区分度所在**。所以 1–3 要快、要标准化、要练到肌肉记忆，把时间省给 4。

## 2. 每个阶段的具体动作与话术

### 阶段 1 · 需求澄清（5–8 min）

澄清清单本身见 [`00-foundations/03-tradeoff-framework.md`](../00-foundations/03-tradeoff-framework.md) 第 1 节。这里只讲**面试执行**。

**只问 6–8 个问题，且每个问题要能改变你的设计。** 问"用户会不会上传头像"这种不影响架构的问题是负分。

四类必问，一类各 1–2 个：

| 类别 | 示例问题 | 它会改变什么 |
|---|---|---|
| **规模与形状** | "读写比（read/write ratio）大概是 10:1 还是 1:10？目标是现在的量还是 18 个月后的量？" | 决定要不要分片（sharding）、要不要 CQRS |
| **一致性边界**（consistency boundary） | "哪条链路上用户看到陈旧数据（stale data）是不可接受的？" | 决定主从读、quorum、还是共识 |
| **可用性与降级**（availability and graceful degradation） | "系统挂 10 分钟的业务代价是什么？可以降级到只读吗？" | 决定多 AZ / 多 region / 降级路径 |
| **成本与合规** | "有 $/请求 的目标吗？数据里有 PII 或驻留（data residency）要求吗？" | 决定存储选型、加密、cell 划分 |

**收尾话术（务必说出来，这是一个明确的评分点）：**
> "我总结一下我要设计的东西：一个读多写少（约 20:1）、峰值 5 万 QPS、p99 200ms、可用性 99.9%、有 PII 需要按 region 驻留的系统。**明确不做**的是离线分析和权限模型的细节。我按这个往下走，中途你觉得跑偏了随时打断我。"

### 阶段 2 · 容量估算（5 min）

方法论见 [`00-foundations/02-capacity-estimation.md`](../00-foundations/02-capacity-estimation.md)。面试里只需要**三个数**：

```
① 峰值 QPS   = DAU × 人均次数 / 10⁵ × 峰谷比(2–3×，秒杀 10–100×)
② 稳态数据量 = 条数 × 单条字节 × 3–5（索引+副本+元数据）
③ 月成本量级 = 计算 + 存储 + 出网 + （AI 系统：token）
```

**每个数字后面跟一句"这意味着什么"，否则算了等于白算：**
> "峰值 4.5 万写 ops/s。这意味着单个 Postgres 主库（约 2 万 TPS 上限）撑不住，所以要么在客户端做批量合并，要么现在就分片。我选批量合并，因为它是双向门（two-way door）。"

**AI 系统额外必算一项**：token 成本。这是 2026 年面试的高频区分点。
```
月 token 成本 ≈ 日轮次 × (输入 tok × 单价 + 输出 tok × 单价) × 30
缓存命中率是这里的支配变量：缓存读 ≈ 输入价的 10%
（三家主流 API 均如此，2026 年中量级，随时变动）
```

### 阶段 3 · 高层设计（10–12 min）

**顺序固定：API → 数据模型 → 组件图 → 主链路走一遍。**

1. **先写 2–3 个核心 API 签名**（含幂等键（idempotency key）、分页游标（pagination cursor））。这一步只要 90 秒，但它逼你确定系统边界，且面试官立刻知道你在设计什么。
   ```
   POST /v1/documents            Idempotency-Key: <uuid>  → 201 {doc_id}
   GET  /v1/documents?cursor=&limit=  → {items[], next_cursor}
   ```
2. **写数据模型骨架**（表名 + 主键 + 分片键）。分片键（shard key）写出来，别等被问。
3. **再画组件图**。从左到右：客户端 → 边缘 → 网关 → 服务 → 存储，异步链路画在下方。
4. **口述走一遍主链路**："用户点保存 → 网关鉴权 → 写服务校验幂等键 → 写主库 → 发 outbox 事件 → 返回 201。"

**不要在这个阶段画监控、日志、CI/CD、Kafka 集群细节。** 它们不加分，只吃时间。

### 阶段 4 · 深挖（15–20 min，唯一的加分区）

**主动提名 2–3 个深挖点，让面试官选。** 提名本身就在展示判断力 —— 你选的点应该是这个系统里**最难的部分**，不是你最熟的部分。

深挖一个点的标准套路（4 步，每个点 5–7 分钟）：

```
① 机制    这个组件内部怎么工作（数据结构、协议、状态机）
② 参数    具体取值 + 为什么是这个值（TTL、并发数、批大小、阈值）
③ 失败    它怎么坏、坏了什么现象、上游怎么感知
④ 边界    到什么规模会失效、失效前的信号是什么
```

第 ④ 步是 Senior 与 Mid 的分水岭。**任何方案，说不出"什么时候会失效"，就等于没有理解它。**

### 阶段 5 · 取舍与演进（5 min，最容易被跳过也最容易加分）

必须说出这四句：

```
1. 【单向门】"这个设计里唯一不可逆的决策是 X（通常是分片键 / 数据模型 / 对外契约）。"
2. 【v0】   "如果 3 个月上线，我砍掉 A 和 B，只保留主链路，能撑到 N QPS。"
3. 【撞墙】 "第一个撑不住的是 C，大概在 M QPS 或 T TB。"
4. 【信号】 "撞墙前的信号是 [具体指标] 超过 [具体值]，我会在监控里设这条告警。"
```

### 阶段 6 · 反问（3 min）

问**关于工程现实**的问题，不问关于福利的问题：
- "你们这个系统上一次严重事故是什么原因？"
- "这个团队的 on-call 负担大概是什么量级？"
- "你们在 AI 基础设施上，是自建推理还是走 API？成本占收入多少？"

## 3. 白板 / 共享文档的组织方式

不管是实体白板、Excalidraw、还是一个共享 Google Doc，**布局固定成这三块**：

```
┌──────────────────────┬──────────────────────────────────┬──────────────┐
│ ① 需求与 SLO（左上）  │ ② 架构图（中央，最大面积）        │ ③ 待办（右侧）│
│                      │                                  │              │
│ QPS  读 50k / 写 5k  │   ┌──────┐   ┌──────┐  ┌──────┐  │ □ 热点租户   │
│ 数据 2 TB / 年增 5×  │   │Client│──▶│  GW  │─▶│ Svc  │  │ □ 分片再平衡 │
│ p99  200 ms          │   └──────┘   └──────┘  └──┬───┘  │ □ 跨region   │
│ 可用 99.9%           │                            │      │ ☑ 幂等（已讲）│
│ 成本 < $0.001/req    │              ┌─────────────▼────┐ │              │
│ ─────────────        │              │  Postgres (分片) │ │ ← 被追问但   │
│ 范围外：离线分析      │              └──────────────────┘ │   暂时跳过的 │
│         权限模型细节  │   异步链路画在下方 ─────────────▶ │   都记在这里 │
└──────────────────────┴──────────────────────────────────┴──────────────┘
```

**三块布局的三个作用：**

1. **左上角的 SLO 卡片是你的"锚"。** 每做一个决策就指着它说"因为 p99 要 200ms，所以这里不能同步调用"。指着写下来的约束做论证，比空口说服力高一个数量级。
2. **右侧待办列表让你可以合法地"暂时不回答"。** 被问到一个会打断节奏的问题时：*"好问题，我记在右边，先把主链路走完再回来。"* —— 这不是回避，这是**优先级管理**，是加分行为。
3. **中央区域保持干净。** 每画一个框就说出它的职责（一句话）。框超过 8 个说明你的抽象层次不对。

**远程面试的额外规矩**：先花 10 秒说"我用左边写需求、中间画图、右边记待办"，让面试官知道去哪里看。他们同时在记笔记，视线成本很高。

## 4. 评分维度与信号：面试官到底在打什么分

多数公司的评分表是 5–6 个维度独立打分，然后合成 hire / no-hire 和**定级**。下面的 L4 / L5 / L6 对应 **Mid / Senior / Staff**（各公司编号不同，看的是行为不是数字）。

| 维度 | L4（Mid） | L5（Senior） | L6（Staff） |
|---|---|---|---|
| **问题澄清** | 问 1–2 个功能性问题就开画 | 问出规模、一致性、可用性目标并写下来 | 问出**业务约束与组织约束**（预算、团队规模、合规、上线时间），并指出题面里隐含的矛盾需求 |
| **结构化** | 想到哪画到哪，需要面试官拉回 | 有清晰阶段，自己控制节奏 | 主动规划时间并**公开说出计划**；能在被打断后无损回到主线 |
| **技术深度** | 知道组件名字和用途 | 知道内部机制与关键参数取值 | 知道**失效模式（failure mode）与规模上限（scaling limit）**，能说出"这个方案在 X 规模失效，信号是 Y" |
| **取舍论证** | "用 Redis 因为快" | "用 Redis 因为读 20:1、可容忍 5s 陈旧；代价是缓存挂了 DB 要扛 20×" | 同 L5，外加**可逆性分析**（reversibility analysis）与"如果约束反过来我会选什么" |
| **沟通** | 需要被追问才展开 | 主动讲清楚，会检查对方是否跟上 | 能把复杂取舍**讲给非专家听**；会主动确认分歧点并推动收敛 |
| **务实性** | 倾向堆技术（K8s + Kafka + 微服务） | 方案与团队规模、时间线匹配 | 会**主动砍范围**（cut scope）；能说出"这一版不做 X，因为收益不值得复杂度" |

**面试官打分时真正在找的信号词**（听到就打勾）：

```
✅ "我假设……如果这个假设错了，设计会变成……"      → 假设显式化
✅ "代价是……我接受它是因为……"                    → 取舍量化
✅ "这个方案到 X 规模会失效，信号是 Y"              → 边界意识
✅ "这是单向门，我愿意在这里多花时间"                → 可逆性思维
✅ "先不做这个，v1 再加"                            → 范围控制
✅ "我不确定，我的推理是……"                        → 诚实 + 推理路径
❌ "一般都这么做" / "业界标准就是" / "肯定没问题"    → 无论证的断言
❌ 被追问一次就改答案                               → 论证不是自己的
```

**一个被低估的事实**：面试官在写反馈时需要**引用你的原话**。说得越具体、越可引用，你的评分越高。含糊的正确 < 具体的可辩护。

## 5. 常见失分点清单

按杀伤力排序。前四条能干掉大多数候选人。

| # | 失分行为 | 面试官记的是 | 修法 |
|---|---|---|---|
| 1 | **直接开画** | "没有需求意识，会造出没人要的东西" | 强制自己前 5 分钟不碰画笔 |
| 2 | **只说方案不说代价** | "不知道自己在放弃什么" | 每个决策后强制说一句"代价是……" |
| 3 | **不给数字** | "凭感觉做架构" | 每个组件后跟一个量级：QPS / 延迟 / 容量 / $ |
| 4 | **不主动收敛** | "45 分钟讲不完一个系统" | 到点无条件切阶段 5 |
| 5 | **被追问就动摇** | "论证不是自己的，是背的" | 追问 = 让你展开，不是说你错。先解释，再评估，必要时才改 |
| 6 | **过度设计**（over-engineering） | "会把团队拖死" | 先给 v0，再给"什么时候升级到 v1" |
| 7 | **忽略失败模式** | "上线会炸" | 每个组件问自己：它挂了会怎样？谁先感知？降级成什么？ |
| 8 | **不管成本** | "只会花钱不会算账" | 至少给出月成本量级和最大的一项 |
| 9 | **沉默思考超过 20 秒** | "不知道他在干什么" | 出声思考（thinking out loud）："我在权衡是把这个放同步还是异步……" |
| 10 | **画了组件但不说数据怎么流** | "图是背的，不是推的" | 画完必须口述走一遍主链路 |
| 11 | **热点 / 尾延迟（tail latency）一个字不提** | "没做过真实规模" | 主动提一次热点分片（hot partition）和 p99 扇出放大（tail latency amplification） |
| 12 | **不区分"我知道"和"我做过"** | 诚信风险 | 说"我没在生产上跑过，但我理解它的机制是……" |

**第 5 条值得展开，因为它最冤枉。** 面试官追问"你确定吗"通常有三种意图：(a) 想听更多细节，(b) 发现你漏了一个 case，(c) 单纯压力测试。**正确反应永远是先展开论证，而不是先改答案。**

> "我还是选异步。你说的场景我理解 —— 如果用户必须立刻看到结果，异步确实不行。但我们刚才确认了这个操作允许 30 秒内完成，所以我用异步 + WebSocket 推进度。如果这个前提变了，我会改成同步返回 job_id 加 SSE。"

这段话做了三件事：坚持、承认对方的合理性、给出前提变化后的方案。**这就是 L5→L6 的沟通信号。**

## 6. 怎么处理不会的问题

**永远不要编。** 面试官几乎都在自己的专业领域出题，编造会被立刻识破，而且会污染你前面所有的可信度。

标准四步：

```
① 承认边界   "我没有直接做过 X。"
② 给推理路径 "但按第一性原理，它要解决的问题是 A，
              约束是 B，所以我猜它的核心机制大概是 C。"
③ 给类比     "这和我做过的 D 很像，D 的做法是 E。"
④ 给验证方式 "如果是真实项目，我会先做一个 N 天的原型测 F 指标再决定。"
```

**示例（被问到不熟的向量索引内核）：**
> "HNSW 的具体图构建参数我没调过。但它要解决的是高维空间里 ANN 的召回-延迟取舍（recall–latency tradeoff），机制上是分层跳表 + 贪心搜索，`efSearch` 越大召回越高、延迟越高，这和 B-Tree 的扇出取舍是同一类问题。如果是真实项目，我会先用托管服务跑一个 100 万向量的基准，测 Recall@10 和 p99，再决定要不要自建 —— 我的先验是 1000 万向量以下不值得自建。"

这个回答**没有一句编造**，但展示了机制理解、类比迁移、和工程判断。**它拿到的分数通常高于一个背出来的正确答案。**

**反面**：说"这个我不太清楚"然后停住。沉默是最差的选项 —— 它把 45 分钟的评估样本削掉了一块。

## 7. 怎么主动驱动而不是被问

系统设计面试的默认失败模式是**变成问答**：面试官问一句，你答一句，45 分钟结束，面试官只看到了他自己想到的那几个点。

**你要坐在驾驶座上。** 三个具体手法：

**a) 每个阶段结束时宣布下一步**
> "主链路我讲完了。接下来我想深挖三个地方：分片键与热点、缓存一致性（cache coherence）、以及跨 region 的写路径。我觉得**热点**是这个系统里最难的，我从它开始 —— 除非你想先看别的。"

**b) 主动暴露你知道的问题**
> "我这里画的是同步写两份，我知道这会把可用性变成两个系统的乘积。我先这么画是为了讲清楚主链路，等下在深挖里我会改成 outbox。"

主动认领问题的收益极高：面试官不需要"抓"你，转而和你一起解决问题 —— **协作感是评分表上的隐藏项。**

**c) 用问题引导面试官暴露他关心什么**
> "这个系统的读扩展我可以走只读副本（read replica）或者缓存两条路，取决于你们更在意一致性还是成本。你们实际的场景里，用户对陈旧数据的容忍度大概是多少？"

## 8. Staff（L6）的额外期待

L5 交付**一个正确的设计**。L6 还要交付**这个设计怎么落地到一个真实组织里**。四条：

### a) 组织影响与康威定律（Conway's Law）
> "这个设计里有 5 个服务，但我们只有 8 个工程师。按康威定律，8 个人维护 5 个服务会导致每个服务都没有真正的 owner。**我会先做模块化单体（modular monolith）**，把服务边界写在代码结构里，等团队涨到 20 人再拆 —— 拆的成本我估是 6 周，比现在就承担分布式复杂度便宜。"

### b) 迁移策略（比新建设计更能区分 Staff）
被问"你要改分片键"时，L6 的回答是一个**六步剧本**（six-step playbook），不是一个方案：
```
1. 双写（新旧两套，新的不读）      ← 可随时回滚
2. 回填历史数据（限速，监控主库 IOPS）
3. 影子读对比（读旧的返回，读新的比对，记差异率）
4. 差异率 < 0.01% 持续 7 天后，按 1% → 10% → 50% → 100% 切读
5. 观察 2 周，旧路径保持可回滚
6. 停双写，删旧路径
```
每一步都要说出**回滚条件**（rollback criteria）。见 [`03-saas-platform/05-release-engineering.md`](../03-saas-platform/05-release-engineering.md)。

### c) 风险管理
> "这个设计有三个风险。最高的是**分片键选错**，概率中、影响是一个季度的迁移；我用一个 2 周的原型跑真实流量分布来降它。第二是**供应商锁定**（vendor lock-in），我在仓储层做一层抽象，成本很小。第三是**成本失控**，我在第一天就上租户级用量计量（usage metering）和硬限额（hard limit）。"

风险要给 **概率 × 影响 × 缓解手段 × 缓解成本**。四项齐全才是 Staff 的表述。

### d) 为他人降低复杂度
Staff 的产出不只是系统，是**别人在这个系统上工作的容易程度**：
- 给出**默认值**：新服务默认带 trace、默认幂等、默认有超时预算（timeout budget）
- 消灭**一整类问题**而不是修一个 bug：不是"给这个接口加限流"，是"网关统一做租户级限流（per-tenant rate limiting），业务代码不用管"
- 写下**决策的复审触发条件**（见 ADR 模板），让继任者知道什么时候该重新想

> **面试金句**：
> "我判断一个平台设计好不好，看的是**第 10 个团队接入的成本是不是低于第 1 个**。如果每接一个团队都要平台组写一次胶水代码，那这不是平台，是外包。所以这里我宁可多花两周把租户注册做成声明式的自助流程，也不做一个更快上线但需要人工开通的版本。"

## 9. AI / 基础设施岗的特殊准备（2026）

这类岗位的面试官通常在做 LLM 网关、Agent 平台、推理服务或 AI 数据平台。他们考的**不是模型**，是**模型带来的新约束**。

**九个高频考点，每个给一句可直接说的锚：**

| 考点 | 面试官在等的锚点 |
|---|---|
| **前缀缓存（prefix caching）经济学** | "缓存读约为输入价的 10%（三家主流 API，2026 年中量级）。所以上下文必须组织成`[字节稳定的前缀] + [只追加的尾巴]`。系统提示里放 `now()` 或未排序的 JSON，等于把缓存全部作废，而且**没有任何报错，只有账单**。" |
| **静默 cache miss** | "`cache_read_input_tokens` 恒为 0 必须做成一条监控指标和告警，不是排查手段。" |
| **上下文不是越长越好** | "[context rot](https://research.trychroma.com/context-rot) 的实证是性能在窗口填满**之前**就单调下降，18 个前沿模型一致；LongMemEval 上约 300 token 的聚焦 prompt 打得过 11 万 token 的全量 prompt。所以 2026 的默认形态是**检索 5 万–20 万 token 再让长上下文模型推理**，不是二选一。" |
| **TTFT / TPOT / goodput** | "容量规划只能用 **goodput**（每秒同时满足 TTFT 与 TPOT SLO 的请求数）。只报 TTFT 会漏掉一个反例：两个都满足 TTFT ≤1.5s 的配置，P95 TPOT 可以差 10 倍。" |
| **PD 分离（prefill–decode disaggregation）不是默认更好** | "[NVIDIA 官方文档](https://docs.nvidia.com/dynamo/latest/)明确说小模型、短 prompt、低并发、无快速 KV 传输时聚合部署（aggregated deployment）更简单更快。判据是 `KV_bytes / RDMA带宽` 和该请求 decode 时长比大小 —— 前者大就不要分。没有 IB/RoCE 回落到 TCP 是最常见的翻车方式。" |
| **KV cache 是最大杠杆也是最大泄露面** | "跨租户共享 prefix cache 已被 [PROMPTPEEK（NDSS 2025）](https://www.ndss-symposium.org/ndss2025/) 实证可逐 token 重建他人 prompt。结论是**同租户内共享、跨租户默认关闭** —— 而这会直接削掉多租户场景的最大性能杠杆。这个张力要显式讲出来，不要假装不存在。" |
| **提示注入（prompt injection）是架构问题** | "概率性防御（分类器、护栏）不能当边界用 —— 已发表的防御在自适应攻击下多数 ASR > 90%。边界只能是确定性隔离：能力最小化（least privilege）、出口管控（egress control）、不可逆动作强制人在回路（human-in-the-loop），且**高影响动作清单必须设计期静态定义**，不能运行时让 Agent 自己判断。" |
| **Agent 成本结构** | "推理占 85–89%，沙箱运行时只占 11–15%，存储近乎 0（[Anthropic 官方算例](https://platform.claude.com/docs/en/about-claude/pricing)，n=1）。所以优化沙箱冷启动（sandbox cold start）是错方向，杠杆在上下文长度、缓存命中率、和子 Agent 的模型分级（model tiering）。" |
| **公开 benchmark 不能当验收** | "Berkeley RDI 把 8 个主流 agent 基准中 7 个刷到接近 100%（10 行 `conftest.py` 拿下 SWE-bench Verified 全部实例）。门禁（release gate）必须是**自有生产轨迹回归集**（regression set），公开分只能当参考。" |

**MCP 相关的时效性陷阱**：MCP 规范在 [2026-07-28 版](https://modelcontextprotocol.io/specification/2026-07-28/changelog)做了破坏性的"去状态化"—— 删掉 `initialize` 握手、删掉 `Mcp-Session-Id`、删掉 SSE 断线续传。**正面收益是 MCP 网关可以删掉粘性路由（sticky routing）那一层**；代价是响应流断了就丢请求，长耗时工具必须走 Tasks 扩展轮询。如果你还在讲"MCP session 怎么保活"，面试官会知道你的知识停在 2025。

**准备方式**：把 [`04-ai-agent-systems/`](../04-ai-agent-systems/) 全章过一遍，然后**只背两类东西** —— 价格与容量的量级、以及每个方案的失效条件。具体 benchmark 分数不要背，它们跨 harness 不可比，背错反而扣分。

## 10. 什么时候不要用这个框架

| 情况 | 为什么框架会害你 | 改怎么做 |
|---|---|---|
| 面试官开场就说"我们直接聊 X 组件" | 那是一场 deep dive 专场，不是完整设计题 | 跳过阶段 1–3，直接进阶段 4 的四步套路 |
| 题目是"debug 这个线上问题" | 这是事故演练，考的是假设-验证循环 | 用 [`05-reliability/04-incident-and-chaos.md`](../05-reliability/04-incident-and-chaos.md) 的思路：先止血、后定位、再根因 |
| 题目极度开放（"设计 Google"） | 澄清阶段会无限膨胀 | 主动切一刀："我把范围收到搜索的索引与查询链路，广告和爬虫我不做。" 收范围本身是加分项 |
| 面试官持续打断、节奏被完全接管 | 硬守时间表会显得不听人话 | 放弃时间表，改用"每答完一个问题主动挂一句下一步"来夺回一点主动权 |
| 剩 10 分钟你还在阶段 1 | 框架已经失效了 | 直接说"我时间用多了，我现在快速把主链路走完，然后讲取舍" —— **公开承认时间管理失误，比假装没事强** |

**反模式（anti-pattern）警告**：把框架背成剧本，然后不管面试官说什么都按剧本演。框架是**时间预算工具**，不是台词本。面试官问你一个具体问题时，你的回答是"这个我等下在深挖阶段讲"—— 这是最讨厌的一种机械执行。**能答就当场答，答完再回主线。**

## 面试官会追问

1. 你只有 45 分钟，需求澄清已经用了 12 分钟，接下来怎么办？
2. 你说要深挖三个点，为什么是这三个？这个系统里最难的部分是什么？
3. 我打断你三次问了三个不同方向的问题，你怎么保证还能收敛？
4. 这个方案什么时候会失效？失效前我在监控上能看到什么？
5. 如果团队只有 3 个人、6 周上线，你的设计要改掉哪几处？
6. 你刚才那个决策是单向门（one-way door）还是双向门？改回去要多久？
7. （AI 岗）你的前缀缓存命中率目标是多少？怎么知道它掉了？
8. （Staff）这个迁移的回滚点在哪？回滚需要多久？谁来按那个按钮？
